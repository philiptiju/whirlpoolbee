Install & Help

Get the client agent running on Windows, macOS, or Linux, and troubleshoot common issues.

1. Install the Client Agent

Run one command on each machine you want to monitor. It downloads client_agent.py, sets up its own tiny Python environment, and registers itself as a background service that keeps running and auto-starts at login — no separate service manager to configure.

Native PowerShell — no Git Bash or WSL required. Works on any Windows 10/11 machine out of the box.

& ([scriptblock]::Create((irm "{{ server_url }}/static/client-install.ps1"))) -ServerUrl "{{ server_url }}"

To point the agent at a different server or watch it run in the foreground first, download and run with parameters instead:

iwr {{ server_url }}/static/client-install.ps1 -OutFile client-install.ps1
.\client-install.ps1 -ServerUrl "{{ server_url }}" -DebugMode

Already have Git for Windows installed and prefer bash? The original installer also works from Git Bash (not PowerShell/cmd.exe): 

curl -fsSL "{{ server_url }}/static/client-install.sh" | bash -s -- --server "{{ server_url }}"
curl -fsSL "{{ server_url }}/static/client-install.sh" | bash -s -- --server "{{ server_url }}"

Custom server or foreground/debug mode:

curl -fsSL {{ server_url }}/static/client-install.sh | bash -s -- --server {{ server_url }} --debug

Installs a launchd user agent under ~/Library/LaunchAgents so it auto-starts at login and restarts if it ever stops.

curl -fsSL "{{ server_url }}/static/client-install.sh" | bash -s -- --server "{{ server_url }}"

Custom server or foreground/debug mode:

curl -fsSL {{ server_url }}/static/client-install.sh | bash -s -- --server {{ server_url }} --debug

Installs a systemd --user service where systemd is available, so it auto-starts at login and restarts if it ever stops.

2. Managing the Agent

schtasks /query /tn ClaudeDashboardAgent /v /fo list   # status
schtasks /end /tn ClaudeDashboardAgent                 # stop
schtasks /change /tn ClaudeDashboardAgent /disable      # disable auto-start
schtasks /change /tn ClaudeDashboardAgent /enable       # re-enable
Get-Content -Wait "$env:USERPROFILE\.claude-dashboard-agent\agent.log"  # tail logs

Uninstall:

schtasks /end /tn ClaudeDashboardAgent
schtasks /delete /tn ClaudeDashboardAgent /f
schtasks /delete /tn ClaudeDashboardAgentWatchdog /f
Remove-Item -Recurse -Force "$env:USERPROFILE\.claude-dashboard-agent"
launchctl list | grep com.claude.dashboard.agent          # status
launchctl stop com.claude.dashboard.agent                  # stop
launchctl unload ~/Library/LaunchAgents/com.claude.dashboard.agent.plist   # disable
launchctl load -w ~/Library/LaunchAgents/com.claude.dashboard.agent.plist  # re-enable
tail -f ~/.claude-dashboard-agent/agent.log                 # tail logs

Uninstall:

launchctl unload ~/Library/LaunchAgents/com.claude.dashboard.agent.plist
rm ~/Library/LaunchAgents/com.claude.dashboard.agent.plist
rm -rf ~/.claude-dashboard-agent
systemctl --user status claude-dashboard-agent    # status
systemctl --user stop claude-dashboard-agent      # stop
systemctl --user disable claude-dashboard-agent   # disable auto-start
systemctl --user enable --now claude-dashboard-agent  # re-enable
journalctl --user -u claude-dashboard-agent -f    # tail logs

Uninstall:

systemctl --user stop claude-dashboard-agent
systemctl --user disable claude-dashboard-agent
rm ~/.config/systemd/user/claude-dashboard-agent.service
rm -rf ~/.claude-dashboard-agent

3. Troubleshooting

Windows: "bash is not recognized" / the curl | bash command does nothing

That command needs a real bash — it only exists on Windows if Git for Windows (Git Bash) or WSL is installed. Use the native PowerShell command from the Windows tab above instead (irm ... | iex) — it doesn't need Git or WSL at all.

Windows: "running scripts is disabled on this system" / execution policy error

The PowerShell one-liner evaluates the installer in-memory. If you downloaded the .ps1 file first and are running it directly (.\client-install.ps1), and see this error, run it with the policy explicitly bypassed and your server URL:

powershell -ExecutionPolicy Bypass -File .\client-install.ps1 -ServerUrl "{{ server_url }}"
Windows: "Python was not found; run without arguments to install from the Microsoft Store..."

This is a fake "App Execution Alias" shortcut, not a real Python error — it appears even when Python is installed. Go to Settings → Apps → Advanced app settings → App execution aliases and turn OFF python.exe and python3.exe, then restart your terminal and re-run the installer.

Python 3.8+ isn't installed at all

Install it from python.org (Windows/macOS) or your package manager (apt install python3 python3-venv, dnf install python3, etc. on Linux), then re-run the install command.

The Sync page shows "X failed" and it isn't clearing up, even after restarting the agent

A failure that survives a full restart is almost always a permanent, data-level issue with a specific session file (e.g. no usable timestamp in it), not a transient network problem — restarting resets the agent's retry bookkeeping, but it will hit the exact same file-level issue again since the file itself hasn't changed. Newer agent versions self-heal common cases like this automatically on their next auto-update (see /api/agent/version for the version currently required). If it persists after that, check the agent's console/log output for the specific error line for that session.

The agent doesn't seem to auto-start after a reboot/logon

Windows: confirm the task exists and is enabled: schtasks /query /tn ClaudeDashboardAgent /v /fo list. macOS: confirm the LaunchAgent is loaded: launchctl list | grep com.claude.dashboard.agent. Linux: confirm the service is enabled: systemctl --user is-enabled claude-dashboard-agent. If any of these come back empty/missing, re-run the install command — it always does a full clean reinstall.

I want to point an already-installed agent at a different server

Just re-run the install command with -ServerUrl (Windows) or --server (macOS/Linux/Git Bash) pointed at the new server — every install does a full clean reinstall first, so there's nothing to manually undo.

Where do logs live?

Windows: %USERPROFILE%\.claude-dashboard-agent\agent.log and agent.error.log. macOS/Linux: ~/.claude-dashboard-agent/agent.log and agent.error.log. A full install transcript is also kept at install.log in the same folder.
